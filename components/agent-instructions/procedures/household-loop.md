# Bounded household-improvement loop — public example

This is a generalized description of the working method, not the installed pilot's permissions or a scheduler configuration. The implementation lives in the sibling `fami-runtime` component. Its example policy starts unqualified with no grants.

1. Read current controls, the scope of the actual commission, pause state and route qualification. Fail closed when a required input is missing. Never reactivate the owner controls yourself.
2. Obtain fresh usage for applicable resource pools, including unresolved reservations and a correction/delivery allowance. Keep the agreed reserve; missing or stale coverage is not zero usage. Do not switch models, redeem credits or incur charges to evade a cap.
3. Reconcile owners and callbacks. A timeout is not evidence that computation stopped. Keep its slot and reservation unresolved until the result or termination is known.
4. Inspect the owning project state and current needs. Retain only necessary authorized information. Personal correspondence and raw account data remain in their owning systems.
5. Select a useful bounded outcome by consequence, deadline, burden removed, reuse and cost. Unchanged observations do not mean useful research must stop. Conversely, spare compute is not a consumption target.
6. Run the gaming preflight before substantial local work. Defer heavy work while the configured game is active; game exit does not independently restart an owner-paused commission.
7. Use the appropriate skill and verify source revisions. Separate approved creative decisions from proposals and recovered transcripts. Ask for unavailable owner decisions while continuing independent work.
8. Admit only qualified work and effect routes. Preserve originals, inspect conflicts, and check actual effects before retrying after a crash. A worktree or Python helper does not sandbox arbitrary host tools.
9. Verify the finished product, return a result capsule and update owning state when it changed. Keep repetitive observations quiet. Report meaningful completion, failure, opportunity or a required decision.

## Improvement

An experiment identifies the failure or recurring burden, the proposed change and a baseline. Compare a known case, an unseen relevant case and a retained success. Evaluate factual correctness, usability and taste separately. Preserve failed evidence and inspect recovery as appropriate.

Measure actual required human time, usable output, collected income and corrected failures. Distinguish setup, voluntary creative collaboration and maintenance. A wake firing, a test passing or a memo existing is not itself a household benefit.

## Boundaries and stopping

Observation, private drafting, project changes, worker dispatch and external effects are separate permissions. A narrow pilot may authorize only the first two even if the runtime can represent all five. Scheduled runs do not inherit every permission from an unrelated direct conversation.

On pause or stand-down, block new admission and effects, preserve recovery and report unresolved work honestly. An expiry restores its original scope. Do not create a new scheduler, standing process or automatic resume from this example.
